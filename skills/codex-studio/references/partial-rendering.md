# 부분 렌더와 버전관리

전체 영상을 매번 만들지 않고 변경 구간만 렌더하고, 원본과 이전 구간을 재사용한다. [실행 템플릿](../assets/partial-render/)은 Sites용 API·화면·구간 계산·로컬 작업자를 포함한다. 설치 시 스킬 안에 함께 복사된다. **기본 로컬 편집실에 자동 연결되는 완제품은 아니다.** 에이전트가 아래 계약에 맞춰 해당 프로젝트 렌더러를 연결하고 검증해야 한다. 연결 전에는 버튼이 동작한다고 안내하지 않는다.

## 지원 범위

현재 템플릿은 30fps 고정 타임라인의 영상 상자 위치·크기·시작/끝과 표시 자막(`tele`) 변경을 처리한다. 기존 오디오는 동일한 절대 시간으로 잘라 넣는다. 나레이션 길이, 전체 장면 재배치, 프레임률 변경은 이 방식으로 처리하지 않는다. 그런 변경은 영향받는 전체 범위를 다시 계산하거나 기존 전체 렌더 경로를 사용한다. 댓글은 렌더 입력이 아니다.

버전은 수정값 스냅샷·부모 ID·변경 구간·상태·재생 조각 목록을 보관한다. 복원은 과거 기록을 덮어쓰지 않고 그 수정값으로 새 버전을 만든다. 완료된 전체 MP4 보관과는 별개이며, 구간 버전을 `versions publish --video`에 전체 영상인 것처럼 등록하지 않는다. 단일 완성 MP4 내보내기는 이 템플릿에 없다. 소스 전환 시 로딩 지연이 생길 수 있으므로 프레임 단위 무중단 재생을 보장하지 않는다.

## 프로젝트 연결

1. 기존 편집실을 유지하고 `assets/partial-render/public/`의 모듈과 `app/api/renders/[[...parts]]/route.ts`를 Sites 체크아웃의 같은 경로에 복사한다. `render-layout.json`은 실제 작업물 데이터로 교체한다. 예시는 10초이며 영상은 포함하지 않는다. `/base.mp4`에 해당 원본 또는 정확한 프레임 매핑을 가진 프록시를 제공한다.
2. 현재 템플릿은 **Site 하나에 작업물 하나**를 전제로 한다. 다른 작업물이나 새 원본에 재사용할 때는 먼저 별도 Site 또는 작업물+원본 버전으로 DB 키와 R2 경로를 분리한다. 기존 `render-head:current`와 구간 URL이 남아 있는데 원본만 교체하지 않는다.
3. Sites 지침에 따라 owner-private 접근을 유지하고 D1 `DB`, R2 `BUCKET`을 선언한다. `schema.sql`의 `records` 테이블이 필요하다. 기존 테이블이 있으면 스키마를 대조하고 정식 마이그레이션으로 적용한다. API는 Sites의 인증 경계를 전제로 하므로 무인증 서버나 공개 사이트로 그대로 배포하지 않는다.
4. 편집실의 `.log` 요소에 패널을 넣는다. `window.editorBridge.getState()`는 `{layout, canWrite, pending, snapshot:{frames,tele}}`를 반환한다. `restore(snapshot)`는 클라우드에 수정값을 저장하는 Promise이며 실패 시 reject해야 한다. 저장 중에는 `pending=true`로 표시한다. 모듈 스크립트로 `partial-versions.mjs`를 로드한다. 시간/텍스트 수정은 렌더 결과로 확인하며, 실시간 미리보기는 기존 편집실에서 별도로 연결한다.
5. 아래 로컬 작업자와 프로젝트 전용 렌더 어댑터를 연결한다. 요청 대기·진행·실패·재시도·PC 오프라인 상태를 표시한다. 저장만으로 AI를 호출하지 않는다. 렌더 버튼은 연결된 작업자에 요청한다.

`render-layout.json` 필드:

- `frames`: 마지막 항목의 `t1`이 전체 길이(초).
- `boxes`: 고유 `key`, 원래 `t0`, `t1`.
- `tele`: 시간순 항목의 고유 `beat`, 시작 `t`, 원문 `text`.
- `snapshot.frames[key]`: `dx`, `dy`, `scale`, `dt0`, `dt1`. 기본값은 0, scale만 1.
- `snapshot.tele[beat]`: `{text}`.

## 로컬 렌더 어댑터

작업자 설정 파일은 신뢰하는 로컬 파일로 두고, 서버 요청에서 실행 명령을 받지 않는다. 예:

```json
{
  "site": "https://YOUR-PRIVATE-SITE.chatgpt.site",
  "state_dir": ".studio-render",
  "command": ["python", "render_ranges.py", "--job", "{job}", "--receipt", "{receipt}"]
}
```

`render_ranges.py`는 프로젝트에서 구현하는 어댑터다. 입력 JSON의 `snapshot`과 `ranges`를 사용하며, 범위는 30fps 정수 `[start,end)`이다. 수정 전·후의 시간 범위와 0.1초 여유를 합쳐 최대 5초씩 나눈 요청이 온다. 각 구간은 전체 장면 합성 결과를 렌더한다. 바뀐 객체만 투명 영상으로 출력하는 방식이 아니다.

어댑터는 모든 범위에 대해 영상·오디오를 같은 시작점으로 맞춘 독립 재생 MP4를 만들고, 다음 JSON을 `{receipt}` 경로에 UTF-8로 쓴다. `path`는 작업자가 읽을 수 있는 절대 경로다. WSL 경로를 Windows 작업자에게 전달한다면 어댑터에서 변환한다.

```json
{"renderedFrames":60,"cachedFrames":0,"totalFrames":300,"parts":[{"index":0,"path":"/absolute/render/clip-0.mp4"}]}
```

캐시 키에는 정규화한 수정값, 구간, 렌더 코드와 설정, 의존 모듈, 원본 영상·음성·폰트·이미지의 해시를 넣는다. 완료 확인 뒤 캐시를 재사용한다. 임시 파일을 완성 캐시로 취급하거나 설정 변경 뒤 예전 결과를 재사용하지 않는다. 템플릿 작업자는 렌더 엔진이나 캐시를 대신 구현하지 않는다.

실제 프로젝트 작업 폴더에서 `python -X utf8 /absolute/skill/assets/partial-render/worker.py /absolute/worker-config.json`으로 시작한다. Python 3.10 이상이 필요하다. 비공개 서비스 인증값은 지원되는 Sites 도구로 얻고 해당 프로세스의 `STUDIO_SITES_TOKEN` 환경변수로만 전달한다. 저장소·설정 JSON·명령 인자·로그에 쓰지 않는다. 프로젝트가 사용하는 비밀 저장소를 활용할 수 있다. 인증이 만료되면 갱신 후 작업자를 재시작한다. PC가 꺼져 있으면 요청은 대기한다. 설치가 시작 프로그램이나 백그라운드 작업자를 자동 등록하지 않는다.

## 검증 후 제공

- 작은 변경에서 요청 구간만 생성되고 원본 나머지를 참조하는지 확인한다.
- 겹치는 두 수정, 원본 복원, 재실행 캐시, 소스 변경 시 캐시 무효화를 확인한다.
- 클라우드 실제 요청→로컬 처리→업로드→완료→구간 앞뒤 재생을 확인한다. MP4 프레임 수·오디오 길이도 대조한다.
- 잘못된 lease, 중복 요청, 업로드 실패, 재시도, 두 기기의 버전 충돌을 확인한다.
- 모바일 화면과 재접속 후 버전 기록을 확인한다. 로컬 검증과 배포 환경 검증을 구분해 보고한다.

저장소의 `node tests/partial-render.test.mjs`는 변경 구간과 겹친 조각의 원본 offset을 검증한다. 이는 각 프로젝트의 렌더 어댑터나 배포된 인증·저장소 검증을 대신하지 않는다.
